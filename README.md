# Pennovia

**Your voice. Your words.**

[![CI](https://github.com/yoldaolmak/Pennovia/actions/workflows/ci.yml/badge.svg)](https://github.com/yoldaolmak/Pennovia/actions/workflows/ci.yml) · Python 3.10+ · MIT · Open source

**Pennovia is an open-source author voice toolkit.** Give it writing you have permission to use, inspect how you write, and use that profile to guide an AI-assisted draft without surrendering editorial control.

Pennovia has one reusable **Python Core**, a command-line interface (**CLI**) for automation, and **Studio**, a local single-panel browser interface for writers. No hosted account, subscription, database, or vendor-specific voice storage is required. Writing analysis runs locally; model generation uses Ollama or a separately configured provider.

## What you can actually do

| Capability | Output |
| --- | --- |
| **Analyze** | Portable JSON profile of sentence rhythm, vocabulary, punctuation, paragraph patterns and recurring expressions |
| **Draft** | Text generated by an optional configured model using your profile and a content template |
| **Review** | Local, explainable heuristic observations about style alignment and common generic phrases |
| **Export** | TXT, HTML, PDF, optional Google Drive upload or WordPress draft. Local exports receive collision-safe filenames |

**Package version: 0.2.0 alpha.** Voice similarity numbers are *uncalibrated heuristics*, not evidence of identity, authorship, lived experience, factual correctness, or publication quality. A human must review generated work.

## Quick start

```bash
git clone https://github.com/yoldaolmak/Pennovia.git
cd Pennovia
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
pennovia --version
pennovia demo
python -m pytest -q
```

`pennovia demo` reads bundled public-domain sample excerpts. By default, without provider credentials it uses **clearly labeled mock text** to demonstrate the complete offline analyze → audit → export flow; it does not prove model-generation quality. To try a running local model, explicitly select `PENNOVIA_BACKEND=ollama`. The demo reports a fallback to mock output if the selected backend fails.

## Pennovia Studio — a single local workspace

Run the browser interface from the same installed package:

```bash
pennovia studio
# Open http://127.0.0.1:8765 (opens automatically)
# Or choose a port without opening the browser:
pennovia studio --port 8766 --no-browser
```

Studio lets you add public HTTPS article links, paste original writing, or choose TXT/HTML/PDF files; analyze a voice profile; export/import profile JSON; choose a model and draft type; edit and re-review a draft; and download TXT/HTML/PDF or send a **draft** to WordPress / Google Drive. Studio includes a small loopback-only server inside the installed package; there is **no separately deployed service**, account, database or new generation engine. It is not a publicly deployed website.

Profile analysis runs locally (article URLs are downloaded from their selected sites). In Studio, draft generation uses **only the explicitly chosen model provider**; Ollama is preselected, but must be running to generate. Cloud credentials must be configured outside the browser. Unlike `pennovia demo`, Studio does not silently substitute mock output. Style scores are heuristic, not a guarantee of author-voice fidelity. See [Studio setup and limitations](docs/CONFIGURATION.md#browser-studio).

## Developer integration

Pennovia's **Python API** is the integration surface for other software; Studio's localhost HTTP endpoints are implementation details, **not a supported remote/public API**. The existing CLI and `VoiceProfile` JSON format remain usable without Studio. See [Python API](docs/API.md) and [Architecture](docs/ARCHITECTURE.md).

## Use your own writing

```bash
pennovia analyze --corpus ./my-articles --author "Example Writer" --out my-voice.json
pennovia generate --profile my-voice.json --type travel_guide --topic "Three days in Lisbon" --backend ollama --out draft.txt
pennovia export --input draft.txt --title "Lisbon guide" --format html --dest downloads
```

You can also supply article links or paste writing without saving files first. Repeat `--url` or `--text` for multiple source documents; mix them with `--corpus` if needed:

```bash
pennovia analyze --url "https://example.org/my-article" \
  --url "https://example.org/another-article" \
  --author "Example Writer" --language en --out my-voice.json

# Paste a longer text directly into the terminal (end with Ctrl+D):
pennovia analyze --text - --author "Example Writer" --out my-voice.json
```

`analyze` and `run` accept the same inputs. Each sample needs at least 51 words. The URL reader fetches public HTTPS HTML/text pages with a small response limit; it does not crawl entire sites or extract JavaScript-rendered articles. For pasted snippets, `--text "Your writing here..."` is also accepted.

Available generation backends: Ollama, OpenAI, Anthropic, OpenRouter and Codex CLI. Follow the [configuration guide](docs/CONFIGURATION.md) for supported setups and provider data boundaries. Ollama requires a running local service; cloud services require your own API key and may require `pip install -e ".[llm]"`. `--backend auto` may choose a configured cloud provider. Set `PENNOVIA_BACKEND` to choose the default CLI backend, or override it with `--backend`.

The `analyze` and `generate` CLI commands refuse to replace an existing profile or draft. Pass `--overwrite` only when replacement is intended; `run --save-profile` uses the same protection. Local `export` remains collision-safe.

To create a WordPress **draft**, set `WP_URL`, `WP_USER` and `WP_APP_PASSWORD`, then choose `--dest wordpress`. The endpoint must use HTTPS. Publication requires an explicit `--publish`; nothing is published automatically by analysis or generation. WordPress accepts one HTML export per command, so multi-format requests are rejected instead of creating duplicate posts.

## Container

```bash
docker build -t pennovia .
docker run --rm pennovia --version
docker run --rm pennovia demo
```

The Docker image is configured for CLI and offline demo commands. Studio binds to loopback inside its process, so Docker port publishing alone does **not** make Studio accessible from your host; for the desktop browser UI, install and run `pennovia studio` on the host. Container output is ephemeral without a mounted volume.

## Data and trust boundaries

- Local source files and pasted writing are analyzed on your computer; selected HTTPS article links trigger requests to those sites. Voice profiles **may contain verbatim sample sentences** from your corpus. Store them accordingly.
- Cloud draft requests transmit selected prompt content, including representative source sentences, to the configured model provider.
- Optional WordPress and Google Drive exports make network requests only when invoked. Studio WordPress export is **draft-only**, while the CLI permits explicit `--publish`.
- Generated facts, quotations and first-person accounts can be incorrect or invented; review them before publishing.
- Use only writing you have rights or permission to process.
